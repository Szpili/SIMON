THE PROBLEM

A signature proves who wrote the number.
It never proves the number is true.

Every decentralized inference network hands you a signed claim and calls it a proof. Ours started the same way. The interesting engineering is in the gap between those two words.

This is the thesis. Say it once, slowly. The rest of the deck is what follows when you take it seriously. That includes the two places where we caught our own errors.

What a receipt proves and what it does not

Proved today

A registered node signed this exact answer as the result of this job.

  • Ed25519 signature over a commitment to the output text
  • Bound to the job id. A valid receipt from another run cannot be reused

Not proved

That the declared model generated it.

  • A malicious node can sign arbitrary text with a correct digest
  • Token counts and timings are signed declarations, not independent measurements

Binding model + prompt + execution + output needs an execution audit. It is not implemented, and the repository says so.

The right-hand column is the one that matters. Most projects show only the left.

Heterogeneous on purpose, and it shows

Two GPUs, two serving stacks, two models, one network. The engine and the model on each result come from the signed receipt, not from a label that we wrote beside it.

RTX 3090 · vLLM 0.27.1

Qwen3.8-27B · full context admission gate

64.94 tok/s

RTX 3080 Ti · Ollama 0.34.0

Bielik 11B · admission gate disabled, and the node says so

6.50 tok/s

A node that cannot measure its own context budget declares that. It does not pretend.

The second node immediately exposed two false statements in our own receipts. The node announced a model that it was not serving, and every receipt claimed vLLM even when Ollama did the work. We fixed both the same day. Heterogeneity is not a feature list here. It is a test instrument. One node alone never surfaces those two bugs.

An honest AMD node adds no false positives

We tested it on one MI300X on 2026-10-11. In the pre-registered test, an honest AMD node flagged the same 5 of 32 prompts as the NVIDIA reference flagged against itself.

Measured on the MI300X

AMD output was byte-identical to NVIDIA on 22 of 32 prompts. A SIMON node ran Qwen3.8-27B on the MI300X. Its receipts verify, and one changed byte is rejected. One card sustained 64 concurrent streams.

Scope and verdict

One 3B model, Q8, llama.cpp, a 20-token window. The verdict is still FAIL, because honest configurations flag prompts. The M3 check stays telemetry.

We publish the result as measured, including the FAIL. Live now: Gemma 4 on an MI300X node.

Why AMD: the cross-vendor question needs their hardware. Raw data and versions are in docs/amd-data. Full write-up: docs/AMD-MI300X-RESULTS.md.

SIMON adds no measurable cost

We sent the same jobs to vLLM directly and through a SIMON node. The client verified every receipt.

Qwen3.8-27B BF16, vLLM 0.27.1, 256 tokens per job. One job takes about 14 ms more. The client ran on the same host, so the WAN is not in these numbers.

Until 12 October a SIMON node ran one prompt at a time, and it lost some parallel prompts. Now the node runs jobs concurrently, with a limit and an explicit busy error. At 16 and 64 streams the SIMON rows are a little higher. We do not claim a speed-up: each job is a separate agent process, so the requests arrive spread out, and the direct client sends them in waves. Read it as no measurable overhead. WHICH MODEL DOES A NODE SERVE? · PILOT

Two layers check which model ran

A receipt shows who signed the output. These two layers check the model from outside the node, through normal SIMON jobs.

The node serves Agent behavior (LIDAR-style) One-word answers (JSD)
another model familydetecteddetected
another size (0.5B, 3B, 7B, 14B)detecteddetected
the same weights in Q4 instead of Q8not detected (0 of 4)detected (0.43 to 0.51, noise up to 0.27)
the same model on another GPU (honest)no false alarm (16 of 16)no false alarm (0.20 to 0.25)

7 model classes on CPU, GTX TITAN X and RTX 3090. Every agent step was a SIMON job with a verified receipt. 4 to 10 fingerprints per class: a pilot, not an error rate.

LIDAR is a 2026 Tsinghua paper. It identifies the model behind an agent from what the agent does. Its authors did not release code or data, so we built our own tasks and references. The second layer follows Bruckner, One Token Is Enough: ask trivial one-word questions many times and compare the answer distributions. Agent behavior finds the family and the size, but it does not see a quantization change. The one-word layer sees it. Neither layer raised a false alarm when the same model moved to another GPU. The thresholds must be set for each declared model. The tasks are public, so a production verifier needs secret, rotating probes. Full report and raw data: docs/VERIFIER-PILOT.md.

Three of our own claims, withdrawn in public

The receipt did not bind the answer

The digest covered metadata. The text traveled unsigned.

Found during a test of whether we can count tokens at all

A constant pretending to be a measurement

Throughput was tokens / 65.0, the figure of one card, applied to every node.

It survived the code, a comment that claimed "hard measurement", and a demo that showed one number on two GPUs

A test that the whitepaper promised and that we never wrote

Both papers said that the client tests whether a receipt is single-use. It did not.

Corrected in both languages. The ledger now gives it somewhere to be true

A fingerprint mismatch triggers a re-audit, not punishment. We will not ship a threshold that we cannot defend. The ledger records work, never a balance, because verified work is not the same as independent demand. The words double the color here, so the table still reads without it.

Idle capacity turned into burst capacity, with a receipt that you can verify

This is not "earn while you sleep". At 350 W, a night of full load is worth less in commodity tokens than the electricity. The value is work that must not leave your machines, and results that you can verify. It is also five GPUs at once on the morning you need them.
